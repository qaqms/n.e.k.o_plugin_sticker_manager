# 回复意图与表情选择

2026-10-15，0.9.2 正式发行准备。仅修改插件。

此前默认流程是模型选择分类，再由插件随机抽一张图。分类中同时包含害羞、
被摸头、主动示爱和鬼脸时，分类相容不代表具体动作与这轮回复相容。

本轮借鉴参考插件的三点：依据回复者意图而非照搬用户情绪；逐图说明表达
动作归属、用途和复合语气；让模型从候选选择具体 ID，不贴切时可以不选。
参考插件的普通分类模式仍会随机，语义检索及辅助模型是可选能力。

## 当前流程

1. 模型决定这句话是否值得配图，选择分类或给出短关键词。
2. `sticker_list(group=...)` 返回该分类逐图说明；query 支持空格或逗号分词，
   多词取并集、同时给 group 时限定该分类。关键词检索最多提供五个候选，
   分类浏览仍受现有目录上限约束；count 表示总命中数，shown 表示展示数。
3. 模型比较说明，区分自己的难过、安慰对方、自嘲和嘲笑，核对对象与强度，
   再用 `sticker_send(sticker_id=...)` 发送。没有合适图片就继续文字回复。

仅给 group 或 query 的 `sticker_send` 为兼容旧调用返回候选；即使只有一张、
给了 force 或额外配文也不会自动发送。Agent 的无参数入口同样改为浏览候选。
指定 ID 不可用时不会尝试另一张图片。面板仍按准确 ID 试发。

候选查询不消耗发送冷却、概率或使用计数，且剔除该角色最近发过和禁用的图片。
实际发送继续走原 Sender，保留冷却、去重、概率、即时/排队和图片反馈规则。
日志记录候选 ID，检索词和配文仍只记长度。

## 图库说明

以动画不同阶段的抽帧核看现有 190 张图，补充逐图用途和标签；重点修正
被摸头与主动摸人、自嘲与评价对方、单纯笑与指人笑、开心与强撑的区别。
分类仅作导航，证据不支持分类名称时，以逐图说明为准，不补造情绪。
抽帧仍可能遗漏极短动作，标注是可修订的解释，不是绝对语义结论。

`tools/official_labels_v3.json` 是这轮人工标注源。
`tools/review_official_labels.py` 生成开发用抽帧图；
`tools/update_official_labels.py` 只重建 manifest，保留媒体成员原始字节，
再由 `tools/split_official_pack.py` 生成随包分片。
正常升级通过现有内容版本和指纹配对，仅更新官方区现有图片的未手改字段。

## 边界与验收

本轮没有接入 embedding、视觉标注服务或第二个在线模型。关键词召回不是
真正语义检索，短关键词未命中时可能漏图；最终贴切程度仍取决于回复模型。
例如用途说明里的“不适合难过”也会包含“难过”，因此召回优先采用正向
用途标签，不能把文本命中当作可直接发送的结论。

当前 N.E.K.O 工具在回复期间提交，没有使用 AstrBot 的完整回复后处理钩子。
模型之后改变文字态度时，插件不能保证未来全文与已发图片绝对一致。

本地回归覆盖候选不发送、单命中仍需 ID、分类与关键词交集、无匹配无替代、
禁用与近期过滤，以及新版说明升级不覆盖手改字段、不补回已删除图片。
真实宿主还需观察：自己难过时是否避免喜庆图；安慰用户时是否避免指人笑；
害羞是否确有触发；被摸头和主动摸人的对象是否一致。测试通过不等于模型
在所有对话中都能作出正确语义判断。

本次未改积极度、提醒间隔或发送限制，也未添加自动换图、补发或输出正则清洗。
插件没有宿主文字流的拦截接口，上述修复是模型指令约束，需要新会话实测；
本地回归只验证指令送达各入口及发送契约，不能证明模型永不外显操作旁白。
