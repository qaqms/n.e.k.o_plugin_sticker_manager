# 表情包管理的后续规划（2026-11-24 草案）

发图逻辑（回复后选图、概率、降级、预填）已定型，本文只规划“管理”这一侧：
图库怎么整理、图从哪里来、标签怎么来，以及面板 UI 重构。
参考了 AstrBot 的 `astrbot_plugin_meme_manager`（下称“参考插件”），但两边宿主、
选图方式和用户形态都不同，逐条标明能不能借鉴。

## 现状盘点

| 方面 | 我们现在有的 |
| --- | --- |
| 组织 | 使用区（≈ 参考插件的“表情包”）→ 分类（带一句话说明）→ 单张图 |
| 单图元数据 | `desc`、`caption`、`tags`、`visible_text`（图中文字）、启停、使用记录、`owner_edited` |
| 来源 | 内置官方包（标签离线做好）、拖拽/选图上传、zip 套图包（manifest v3）、收件箱目录 |
| 输出 | 导出套图包 |
| 面板 | 一个页面、两个标签页（图库 / 设置），单图详情会整页替换；约 3200 行 TSX、34 个 action |

**最大的短板：用户自己导入的图几乎没有标签。** 上传时 `desc` 只取文件名，
而选图模型完全靠文字描述挑图——没描述的图基本选不中。官方包效果好，是因为标签是离线精修的。

## 参考插件有什么、对我们值不值

| 参考插件功能 | 对我们 | 说明 |
| --- | --- | --- |
| **视觉模型自动写描述+标签**（语义化） | **高，优先做** | 正好补上面的短板，见下文第 2 阶段 |
| 资源广场（GitHub 索引、一键安装、更新前逐图对比） | 中，后做 | 需联网权限和内容来源；版权要逐包确认 |
| 导入别家包格式（manifest + `memes/<分类>/`） | 中，便宜 | 只做一个导入转换器，就能用上现成的社区包 |
| 多包混用、按会话/人格绑定 | 中低 | 我们是单用户陪伴，可改成“按角色（lanlan）选使用区” |
| 语义向量检索 | 低，暂不做 | 要嵌入模型，宿主没有这类用途；我们的候选预筛+模型选图已够用 |
| 从聊天里自动收集图片 | 低 | 群聊场景才有大量图源；可以以后做“收藏这张”之类的手动入口 |
| 图床同步（R2/WebDAV…） | 不做 | 本地插件，导出套图包即可备份 |
| 四种选图模式 | 不做 | 我们只有一种回复后选图，已验证效果好 |

需要“鉴别”的几个关键不同：
- 宿主模型额度共享：参考插件用户自配模型；我们默认跟随宿主的使魔模型，**免费额度是和猫娘的其它任务共用的**，批量识图必须限速、可暂停、有每日上限。
- 权限：现在只声明了连本机。下载要联网，需要新增 `system.network:connect` 并列出主机，用户会看到授权提示。
- 面板是宿主托管的 TSX（`@neko/plugin-ui` 组件），不是参考插件那种自带网页，布局能力受组件库限制。
- 我们的套图包格式刻意不兼容别家（见 `core/pack.py` 头注释），要兼容就单独写“导入转换器”，不改自己的格式。

## 关于“自动填标签”——参考插件里确实有

参考插件的“语义化”页：用**视觉模型**逐张看图，输出一到两句“这图在聊天里表达什么”的描述
和 6–10 个中文标签；支持批量、进度、继续/重试失败、人工修改后锁定、提示词版本号。
GIF 会抽多帧一起送给模型。它的提示词很讲究“谁在说谁”“图里文字原样保留”这类表情包特有的坑，值得借鉴思路。

我们这边已确认的宿主能力（宿主 main `fb81d74`）：
- 插件模型用途可以声明 `capabilities = ["image_input"]`；
- 宿主的使魔模型槽位声明了 `image_input`，**新安装时会自动绑定**，和现在的选图模型一样免配置；
- 网关按消息里有没有图片内容自动识别为识图请求。

还没确认的：宿主免费的使魔模型**实际上能不能看图**、看图的速度和额度消耗。这要先做一次实测再定方案。

我们已有可复用的部分：`core/labeling.py` 的规则（主人改过的字段不被覆盖、值没变不写盘）
本来是给官方包刷标签用的，自动标注可以沿用同一把尺。

## 分阶段规划

### 第 1 阶段：面板 UI 重构（不加功能）

> **进度（2026-11-24）**：维护者选定方案 A（分类侧栏 + 网格 + 侧栏详情）并加上方案 B 的概览页，
> 已实现：四页“概览 / 图库 / 导入 / 设置”，宽屏侧栏详情（< 960px 整页），明确的选择模式，
> 缺描述筛选，导入页集中导入、导出与体检。面板回归测试 36 项、浏览器视觉测试 5 种宽度与深色模式通过，
> 宿主 `check --release` 通过；尚未在真实宿主里试用，未发行。

先重构，是因为后面的“待标注”“导入队列”“下载”都需要地方放。

现在的问题：
- 主要操作藏在多层折叠菜单里（使用区菜单、工具栏“更多”、分类菜单），找不到；
- 设置页把常用开关和诊断信息混在一起（`awareness_card` 一个组件就 378 行）；
- 单图详情整页替换，看完要退回去重新找位置；
- 顶部有开关、使用区、标签页、批量条、提示五层东西叠在一起。

拟定的信息结构（待出效果图确认）：
1. **概览**：发图开关、选图模型状态（正常 / 已降级到工具模式）、配图概率、当前使用区、图片数、待处理数。
2. **图库**：宽屏左侧分类目录、右侧网格（参考插件这一点做得清楚）；明确的“选择”模式；详情改成侧栏或弹层，不离开列表。
3. **导入**：拖拽、zip、收件箱集中到一处，显示每批导入结果；以后自动标注和下载也放这里。
4. **设置**：频率、冷却、模型；诊断和高级项默认收起。

做法：先列出 34 个 action 和每块状态，确认组件库有哪些布局能力（侧栏、弹层、表格），
出 2 套效果图给维护者选，再按页面分批替换；每批保持现有面板测试通过。

### 第 2 阶段：自动标注用户导入的图

1. **实测**：加一个临时的“测试识图”，用宿主免费模型看 3–5 张图，记录能否识图、耗时、额度。不行就退回“用户自绑识图模型”方案。
2. 新增模型用途 `labeling`（`image_input`），文字选图模型不受影响。
3. 导入后进入“待标注”队列，后台逐张处理：限速、可暂停、每日上限、失败可重试；面板显示进度。
4. 输出写入 `caption`、`tags`、`visible_text`，并从**已有分类**里建议一个分类；主人改过的字段一律不覆盖。
5. 可选“人工确认”：标完先放待确认，确认后才参与选图。
6. GIF 抽帧需要 PIL 进包（`docs/sticker-system-study.md` 已列为体积决策），第一版可以只送首帧。

### 第 3 阶段：更多图源

1. 导入转换器：支持参考插件那类“manifest + 分类目录”的 zip，分类说明一起带过来，再交给自动标注补全单图描述。
2. 从链接导入：贴 GitHub 仓库或 zip 地址下载。需要新增联网权限（只列 `github.com`、`codeload.github.com` 等主机）。
3. 资源广场（可选，最后做）：要有可靠的内容来源和逐包许可证明；否则只做“从链接导入”。

### 第 4 阶段（视需求）

- 按角色选使用区（多个猫娘各用各的图）；
- 清理档位遗留字段（交接文档待办 3）；
- “收藏这张”：把聊天里用户发的图加进图库。

## 需要维护者决定的事

1. 先做 UI 重构还是先做自动标注（建议先 UI，或先只做第 2 阶段第 1 步的识图实测，两者不冲突）。
2. 下载功能的内容从哪来：只支持用户自己贴链接，还是要维护/接入一个表情包索引；版权怎么把关。
3. 自动标注默认是否需要人工确认。
