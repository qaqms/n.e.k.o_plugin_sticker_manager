# 表情包管理

让 YUI 在聊天中自主挑选并发送合适的表情包，也为你提供一个整理和管理表情收藏的面板。

**插件 ID：`sticker_manager` · 作者：qaqms**

## 能做什么

- **聊天配图**：猫娘通过 `sticker_list` 和 `sticker_send` 查看当前收藏、按分类或关键词挑图；不需要每次手动指定图片。
- **内置收藏**：随包提供 190 张表情及分类信息，首次启动自动导入。
- **分区收藏**：按“区 → 分类 → 图片”整理图库，只让猫娘使用当前激活区；浏览其他区不会自动改变她的选图范围。
- **导入与整理**：收集 PNG、JPG、GIF、WebP，支持批量导入、搜索、勾选、移动分类与删除。
- **图片详情**：查看原图和动画，编辑说明、使用情境、标签与图中文字；返回时保留图库的搜索和选择。
- **发送偏好**：矜持、自然、爱发三档积极度，配合冷却、最近去重和提醒间隔控制节奏。
- **迁移收藏**：导入、导出套图 ZIP，保留图片及说明、标签、分类信息。

随包附带 **190 张表情、22 个分类**。首次启动会收进面板的“官方”区；删除后可通过“恢复官方收藏”重新导入。“官方”是插件内置收藏区的名称，不代表 N.E.K.O 项目对素材来源或版权作出背书。

素材以分片文件随包提供，插件直接读取，不额外下载，也无需手动合并。分片仅改变存储方式，不改变图片与动画。

## 安装

本插件需要 N.E.K.O 宿主，不能单独运行。
需要宿主提供 Hosted TSX 面板、LLM Tool Calling 和插件图片消息接口。
SDK 声明：推荐 `>=0.1.0,<0.2.0`，支持范围 `>=0.1.0,<0.3.0`；
这不是对所有历史安装版的实测保证，具体导入与聊天行为请以目标宿主验收为准。

请从插件市场或本仓库的 **Releases** 获取已发布版本的 `.neko-plugin` 安装包。
若入口尚无可安装版本，表示版本发布尚未完成；源码 ZIP 不是安装包。

1. 获取 `.neko-plugin` 安装包。
2. 在 N.E.K.O 的插件管理中导入安装包，确认安装或替换同 ID 插件。
3. 启动插件，打开“表情包管理”面板。
4. 在发送设置中打开总开关。**默认关闭**，不开启时猫娘不会查看目录或发表情，但你仍可整理图库。

市场版本以实际审核和发布结果为准；GitHub Release 的存在不等于已在插件市场上架。

更新时直接覆盖导入，不需要先卸载。正常更新会保留用户配置与图库；不要选择“清除数据”，除非确实打算删除收藏。`0.9.0` 是版本重定号，相较开发版本 `0.20.x` 数值更低，已安装用户应使用明确确认的手动替换，不应依赖自动升版提示。

## 第一次使用

**直接使用内置收藏**：激活“官方”区，开启发送总开关，积极度先选“自然”，然后开始新对话。可以先明确说“发一个表情包”检查调用链，再观察日常聊天中的自主配图。

**建立自己的收藏**：创建一个区，在其中新建分类，写一句分类适用的情境，例如“轻松接话或表示赞同”。把图收进对应分类，再将这个区设为激活区。逐图说明不是必填项；分类情境写清楚更有助于猫娘选择。

切换或更新插件后建议开始新对话。工具由宿主和模型共同决定是否调用，积极度更高也不保证每轮发图。

## 常用设置

多数设置可以在面板调整。完整配置字段见仓库内的 `config.example.toml`。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 发送总开关 | 关闭 | 允许猫娘读取当前图库目录、收到提醒和发表情 |
| 配表情积极度 | 自然 | 调整配图意愿，不绕过冷却和去重 |
| 发送冷却 | 20 秒 | 同一角色两次图片发送之间的最小间隔 |
| 最近去重 | 5 张 | 自主选图时避开该角色最近成功发过的图片 |
| 放行概率 | 1.0 | 默认全部放行；调低后可能拒绝已选中的图片 |
| 提醒最小间隔 | 60 秒 | 限制相邻配图提醒的频率；不是发图计时器 |

提醒在本地结合用户轮次与有限情绪线索触发，不为情绪判定额外调用模型。总开关关闭时，提醒也不生效。

## 动图与发送限制

收藏、详情和导出保留内置 GIF 的原始字节。聊天发送使用原图或预算内的动画 WebP；为满足大小限制，发送版可能有损压缩或缩小尺寸，但不会替换收藏本体。图库缩略图是静态图，详情和聊天才播放动画。

- 单张导入图片最大 **8MiB**；面板分块直传总量最大 **128MiB**。
- 单个套图包最多导入 **512 张**；超出部分计为拒收，收件箱源包保留。全库导出超过 512 张时明确拒绝，不生成无法完整导回的包。
- 分类名全库唯一。向另一区导入同名分类的新图片会计为拒收，不会静默进入原分类所在区；相同图片仍按重复处理。
- 发送内联预算默认 **256KiB**。较大的静态图通过宿主上传发送；超预算动图默认拒绝，不静默压成首帧。
- 表情包独立显示为插件图片消息，不伪装成猫娘的普通文字气泡。
- 工具发图默认即时提交，可能先于普通文字回复的剩余内容出现；不保证在全部文字或 TTS 结束后发送。
- 兼容排队发送是可选配置，依赖宿主日志信号，不能作为精确的前端播放完成回调。

## 数据与隐私

图库、用户配置和使用台账存放在宿主选择的用户数据根，正常代码更新不覆盖这些数据。Windows 默认位置为 `%LOCALAPPDATA%\N.E.K.O\plugins\sticker_manager`，迁移存储根后可能不同。

插件没有独立外部遥测或自动更新服务器。它使用宿主消息总线观察轮次，调用本机接口检查角色和工具状态；开启兼容排队时还会只读主日志的新增完成记录。提醒会进入模型上下文，选图目录也会提供给模型；图片发送和宿主模型请求仍遵循宿主的网络配置，不代表整个工作流完全离线。

使用台账供最近去重与排序，不保存可选配文或检索词的原文。导出的套图包含你收集的图片与说明，分享前请确认其中没有个人信息。反馈问题时请脱敏日志，不要公开整个用户数据目录。

## 常见问题

**开启后还是不发图？**

先检查插件是否运行、发送总开关是否开启、当前激活区是否有可用图片。新对话中明确请求一次表情包；若可以发送但日常聊天较少配图，可调整积极度。没有工具调用和选图后被冷却、去重拒绝是不同问题，运行状态与日志可帮助区分。

**GIF 在图库里不动？**

图库墙使用静态缩略图。点开详情查看原始动画；聊天显示另以发送素材为准。

**更新后会重新添加被删掉的内置图吗？**

正常升级不会补回主动删除的图片，也不会抢回移到自定义区的图片。只有主动使用“恢复官方收藏”才重新导入缺少的收藏。

**在哪里查日志？**

Windows 默认日志目录为 `%LOCALAPPDATA%\N.E.K.O\logs`，插件日志在 `plugin` 子目录。宿主迁移过存储根时，以实际存储位置为准。

## 开发与发布

市场首次上架流程是：推送源码并通过远程 Verify → 提交仓库的固定 commit 审核 → 审核通过 → 标准 GitHub Release → 通知市场发布版本。
本地导入包用于测试；它不能代替首次审核，也不应手动上传后就视为已完成市场发布。
完整规则见 [更新与发布](https://github.com/qaqms/n.e.k.o_plugin_sticker_manager/blob/main/docs/updates-and-release.md) 和 [官方发布教程](https://project-neko.online/zh-CN/plugins/cli)。

运行时插件不额外依赖第三方 Python 库。开发测试需要 Python 3.11+、uv；素材构建与测试使用 Pillow，面板检查需要 TypeScript。

在插件源码根目录运行：

```bash
uv sync --group dev
uv run python tools/release_gate.py
node tests/hosted_ui_regression.cjs --node-modules ../N.E.K.O/frontend/plugin-manager/node_modules
uv run python tools/build_package.py --host-root ../N.E.K.O
uv run python tools/inspect_package.py ../dist/sticker_manager_v0.9.1.neko-plugin
```

宿主源码默认位于相邻的 `N.E.K.O` 目录。校验和元数据探测在隔离副本中执行，不安装到正在运行的宿主；产物默认写入相邻 `dist` 目录。测试、开发工具、内部文档、缓存和用户数据不进入安装包。

源码仓内文档：`docs/updates-and-release.md` 说明市场审核和发布步骤，`DESIGN.md` 记录实现约束，`CHANGELOG.md` 保留版本历史。发布操作会推送标签并触发远程工作流，应与本地验证分开执行。
