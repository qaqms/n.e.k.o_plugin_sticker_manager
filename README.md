# 表情包管理 (sticker_manager)

给她一个自己的表情包收藏间。

**开张即存货**：随包内置 190 张官方收藏（全部保动画的贴尺 gif），首次启动自动收进「官方」区——
只播一次，拆掉后面板 tab 尾可一键「恢复官方收藏」（v0.12.0 J-2）。

主人先选**区**（分类的上层：J-1 三层「区→分类→图」，她只感知当前激活的那个区），
再**建分类**（名字 + 一句“什么时候用这一类”），点分类块头的「收图进这一类」
把图收进来（想逐图补什么，点开图在聚焦卡里改）；猫娘通过
`sticker_list` / `sticker_send` 两个工具在对话里自主挑一张发出去。
每次发送（含失败的尝试）都记进使用台账——台账在幕后供跨轮去重与最近爱用排序，面板不再展示明细。

日常聊天或明确要求「发一个表情包」都由主聊天的 `sticker_send` 配图。
面板按 `id` 试发指定图的行为不变。旧 `send` 入口的 `id`、`group`、`query`、
可选配文 `text` 与无参数选图仍保留调用兼容，但不再作为自动后台 Agent 兜底入口。

## 积极模式聊天提示（v0.20.15）

本版只优化「爱发／积极」档的提示语：轻松接话、开心庆祝、撒娇贴贴、关心安慰、
玩笑吐槽和犯困道晚安时，优先配一张与猫娘回复态度贴切的图，不用等主人主动要图。
文字已经说清楚，也可以自然配图；一条回复最多一张，正经办事或没有贴切分类时仍纯文字。
按她要表达的态度选择当前分类，不能把对方的状态直接当成她自己的状态。

「自然」「矜持」档、默认档、提醒触发与间隔、冷却、去重、概率和工具参数均不变。
保留主聊天即时 `blind` 发图、工具注册恢复和后台 Agent 自动路由隔离，不代替模型随机发图。
升级保留原有配置和表情包库；本版不承诺固定发图概率。
导入后重启宿主并开始新对话，确认积极度为「爱发／积极」，保持 API 配置不变，
自然聊天约 10–15 轮，不刻意要求发图，再结合日志检查主聊天调用和实际投递。

## 工具恢复与诊断（v0.20.14）

工具注册巡检独立于提醒开关，每 **10 秒**核对一次各角色的 `sticker_list` /
`sticker_send`；一个角色缺少工具时，不再因为另一个角色仍有工具就判定健康。
只在接口可达、明确显示缺失时重发原工具注册，保留当前分类目录和参数，不先注销工具。
不可达、失败响应或不认识的数据形状只记为未知，不盲目反复注册。

补挂后先标记为待确认，后续查询确实看到工具才记录恢复成功。
真正提交提醒前，也会检查提醒目标角色的注册表；复用的短时缓存带检查时刻和缓存年龄。
日志中的 `awareness tool preflight`、`tool_registry`、`reissues`、`confirmations`
分别帮助判断提醒时的登记状态、补挂次数和后续确认。诊断故障不改变原有提醒资格。
这些读数只证明**宿主注册表**的状态，不证明实际模型请求携带工具或模型消费了提醒；
`tool_gaps=0` 也不代表每一轮工具都持续可用。日志不记录聊天原文或完整提示。

实机复测分两组：先明确要求发一张表情包，验证调用链；再正常聊天约 30 轮，观察自主调用。
先完成 API 设置，再最后启动插件；测试期间不保存 API 设置、不切换模型或角色。
也可另做一组配置保存后的恢复测试，检查是否出现缺失、补挂、确认的连续日志。
升级保留原有库、用户配置、积极度、提醒间隔、冷却和概率，不自动代替猫娘随机发图。

## 主聊天与后台任务（v0.20.13）

全部 28 个面板与库管理入口使用宿主已有的 `metadata={"agent_auto": false}`，
从自动 Agent 的候选中退出；入口没有删除，面板按钮与显式 API 调用仍可用。
`sticker_list` / `sticker_send` 两个主聊天工具保持注册，不改工具名、参数、积极度、
提醒设置或发送规则，也不把它们限制到某个角色。

2026-10-02 的 Steam 日志确认后台实际执行的是 `entry=send`，连「摸摸」等日常互动
也会被评估为插件任务，而不是 `sticker_send` 在内部转交了 Agent。
本版收回这个静态入口的自动曝光，不靠静默回执隐藏猫爪任务。
是否停止后台任务仍依赖实机宿主识别上述元数据；本地宿主已支持该规则，
并单独过滤动态 `__llm_tool__` 入口。旧宿主若不支持这些边界，插件不能承诺彻底禁用后台路由。

已有的默认即时发送与自产工具图片 `blind` 展示继续保留。0.20.3 与 0.20.8 的
提醒服务、轮数观察、情绪判定与巡检文件相同，积极度判据也没有收紧；
已确认的投递回归是中间版本强制等待回复结束，期间新输入取消已选图。
「模型不调用」与「调用后图片未提交」必须分开看；本版不承诺模型配图概率必然提高。
升级后重新开始对话，验收主工具调用、实际图片提交和后台任务三项，
不要把重启时保留的历史话轮或后台兜底发送当作新的主聊天调用。

## 对话配图（v0.20.11）

日常配图统一优先使用 `sticker_send(group=分类名)`：按猫娘想表达的态度选择当前激活区的
真实分类，组内自动选图，不需要先查列表或记住图片 id。指定某张图才填 `sticker_id`；
普通回复照常发送，`text` 留空只配独立图片，额外配文仍兼容分条发送。
自然／爱发档的提示明确包含摸摸、贴贴、玩笑与轻松接话，不只等待明显的情绪形容词。

本地提醒新增受限完整短句识别，例如「摸摸」「摸摸头」「不摸了」「贴贴」「蹭蹭」。
它不匹配「请把摸摸替换成问候」「帮我查摸摸鱼游戏」这类事务句中的相同子串；
原有情绪词识别不变。命中只允许提前考虑提醒，不自动代替猫娘发图，不绕过提醒时间限制。
提醒只保留配图路径与档位意愿，不再预告拒绝规则；真正被拒时仍返回对应原因和重试指引。

0.20.11 当时保留后台 Agent 兜底，**因此 Agent 发图仍可能出现在猫爪任务中**。
0.20.13 已将管理入口退出自动 Agent 候选。主聊天工具与后台任务
是不同路径，不通过更改静默返回值来隐藏任务卡。日志新增 `sticker_send_calls` 与
`agent_send_calls`，分别计主工具处理函数和 `send` 自动选图分支的调用数；目录查询、
纯 id 试发分支、队列后续投递
不增加这些入口计数。它们不等同于所有上游模型决策，动态工具入口理论上也可能由 Agent 调用。

本轮修复的是日志已证实的互动触发遗漏与文案冲突，不能保证模型调用率提高。实测时从导入后
的新对话起算，正常聊天至少约 30 轮，再结合 Main／Agent 日志比较；插件启动时可能读到保留的
历史消息，不能直接拿累计 `turns` 当作新测试轮数。宿主、Steam 安装与用户配置均不由开发过程修改。

## 自产图片反馈（v0.20.12）

2026-10-02 的 Steam 测试中，主聊天工具成功发图后，这张图片被 `read` 加入下一轮输入，
聊天从 `free-model` 切到了 `free-vision-model`。宿主文字客户端在图片进入历史后，
本会话继续使用视觉模型；这是一条已确认的额外路由，但还不能证明它是低配图频率的全部原因。

现在工具选图的即时和排队路径都使用 `visibility=["chat"]` + `ai_behavior="blind"`：
图片仍显示在聊天里，不再把自产图片或可选配文当作下一轮输入。工具回执仍提供
`sent` 与 `desc`，猫娘知道选图结果；若追问图片中的具体画面，她只能依据图的资料，
不能把资料当作视觉识别。用户主动发送的图片、面板试发与后台 Agent 的 `read` 行为不变。
静默提醒仍使用 `read`，不会因为此改动失去上下文投递。

本版不调整配图提示词、三轮提醒、0–60 秒提醒设置、冷却、去重或概率。
发图日志新增 `ai_behavior`，便于区分工具输出与后续输入；`sticker sent` 仅表示本地
传输接受，不代表宿主已展示。导入后应开始新的对话，避免旧会话已有图片的视觉路由继续保留。
验收先看工具发图后是否还出现自产图片引起的模型切换，再比较实际调用数；不承诺必然提高频率。
0.20.12 当时保留后台 Agent 兜底；0.20.13 已将管理入口退出自动 Agent 候选，
旧入口的显式调用兼容仍保留。

## 发送时机（v0.20.12）

普通对话中的猫娘调用 `sticker_send` 时直接提交图片，不再等待主日志完成标记；
这样连续输入不会把已经选中的图片以 `turn_superseded` 丢弃。
工具选图使用 `ai_behavior="blind"`，图片可立即展示，不要求模型另起回复，也不反馈为下一轮图片输入。
图片可能先于普通回复的剩余文字出现，不承诺排在全部文字或 TTS 之后。
`[sticker_manager.send].defer_tool_sends` 默认 `false`，旧配置没有此键也自动采用即时发送，
不需要手动改配置。只有显式设为 `true` 才恢复旧版工具排队行为。
后台 Agent 在当前角色没有正在生成的回复时也直接发送，有回复则排队。
排队路径检测到本轮生成结束后，再留默认 2 秒的逐段显示兼容缓冲，然后发出图片；
普通回复仍由猫娘自己的文字通道发送，表情包始终独立成条。
兼容保留可选 `text`（≤500 字），只用于额外配文：配文先单独一条，图片随后单独一条，
两条都署插件名；不把普通回复塞进工具参数，也不在正文重复配文。留空时只发一条图片。
正常文字回复时仍可调用 `sticker_send(group=分类名)` 配一张独立表情包，`text` 无需填写。
0.20.8 只澄清“正常正文与工具配图并不互斥”：0.20.7 的一段观测中工具已注册却没有调用，
目前没有证实是这段措辞造成，也不保证澄清后调用次数恢复。
GIF 原字节、冷却、去重与概率规则不变，使用台账和成功次数只在真正提交发送后增加。
面板试发立即发送。
`sticker_send` 的已排队回执只约束本轮不要重复调用，不要求她以后都不再发表情。
即时与显式开启排队的工具选图在真正投递时都使用 `ai_behavior="blind"` 只作展示，
不反灌进下一轮上下文；面板和后台 Agent 保留原有 `read` 行为。

以下说明仅针对**排队路径的 Steam 兼容适配**，默认工具即时发送不依赖这些信号。
适配只在插件侧实现，不修改宿主，也不增加 SDK 参数：
只读当前存储目录 `logs/N.E.K.O_Main_*.log` 的新增、角色匹配的
`turn_end analyze check` 记录，本机 `/api/debug/health` 仅作辅助保护：
它明确显示角色已开始生成新回复时，取消旧图；空状态或接口不可达不替代日志信号。
每秒检查一次。关闭消息合并时，前端仍可能在生成结束后每隔两秒追加一段文字，
所以保留 `[sticker_manager.send].reply_tail_display_buffer_sec`，默认 `2.0`，范围 `0..30`；
设为 `0` 可恢复生成结束后无额外显示缓冲。升级时已有配置未写此键会自动采用默认值，
不需要手动修改配置；已显式设为 `7.0` 等自定义值的覆盖配置保持不变。
**2 秒只是逐段显示的兼容缓冲，不是前端真实结束信号，也不保证后续文字已经显示完或 TTS 音频播放完毕**。
图片仍署插件名，
不会合并或伪装成猫娘的文字气泡。

宿主目前没有正式的普通回复完成插件回调，日志也没有可关联的工具/话轮 ID，
所以此适配不能承诺在所有抢话、取消或未来版本中精确关联原话轮。
缺少日志时拒绝排队；日志丢失、同角色出现新用户输入或后续结束标记、发现后续回复、
等待超过 5 分钟、关闭插件、禁用/删除图片或切换激活区时丢弃待发图。
没有生成结束信号时不会只靠缓冲计时发图，也不会在重启后补发。
0.20.5 的默认 7 秒缓冲在连续输入时暴露了发送次数回归：实机三次调用全部在推送前
被 `turn_superseded` 取消，并非图片已提交却被 `blind` 隐藏。
0.20.6 只把默认缓冲缩短为 2 秒，增加下一轮输入前的发送机会，取消保护保持不变；
快速连续聊天仍可能使上一轮没有表情，不会把旧图延后补进新轮。
0.20.9 默认绕过工具排队，消除这条已证实的取消路径，但不改变模型是否调用工具的决定。
概率、冷却、去重与积极度不变，也不能承诺升级后发送次数一定恢复。
队列仅存内存，每角色最多一张、全局最多八张。
插件只保留短暂的日志读取游标，不复制聊天日志或把配文写入使用台账。
配文与图片是两次独立提交，不具备事务性：会先验证并构造好图片，
但配文提交后图片仍可能被传输拒绝。此时如实报告 `text_submitted=true`，
保留图片失败原因，只记一次失败尝试，不把它记为图片成功或推进冷却；
不会自动重发已经提交的配文。这里只确认本地传输已接受，不保证宿主已经展示。

| 分类优先（轮 I） | 默认空库什么都没有：先在区内点「新建分类」写名字（必填）+“什么时候用这一类”（可留空），建完就能往它里收图。**收图不问逐图字段**（描述交空串，目录正文按回落尺取分类说明），想逐图改就点开图用聚焦卡。**删分类 = 连带删它里的图**（1C 拍板），确认里先摊精确张数 |

| 官方区（J-2/J-3） | 官方收藏 190 张随包内置（`official/official_pack.zip`，manifest v3 + `pack_version`）；**已分好 22 类、逐张标了梗义**——她看到的目录正文是「一切都好（冒烟版）」这种话，不是文件名；首启播种只播一次（`official_seeded` 台账，脏包不盖章下拍重试）；区的真身是 `builtin` 位，同名手建区就地收编；**空库才默认激活官方区，旧库升级不抓台**；官方区不在册时 tab 尾可一键「恢复官方收藏」（`zone_restore_official`，吃指纹查重不重入）；tab 带「官方」徽章。**标签随包下发（J-3）**：包版本比库里新（catalog 顶层 `official_pack_version`）时，按内容指纹把官方区条目的文本刷成包里的版本——不重进图、不动启停与台账；主人改过的措辞（desc/caption 任一）整块归主人不被包消音，分类与标签照刷 |
| 轻打标 | 逐图文本全可选：一句**分类说明**就是她看到的分类目录正文；目录行正文回落 `梗义>描述>分类说明>未标注`，不造假描述；逐图归类**只能从已有分类里选**（Select，不再是自由输入——手打新名字会静默立一个没说明的分类）；批量勾选即可加/删标签、移入分类、启停、删除 |
| LLM 工具 | `sticker_list`（看目录）、`sticker_send`（按 id / 分类 / 关键词发；**表情包独立成条，可选 `text` 仅作额外配文先单独发送**），带**注册心跳**：每 10 秒逐角色检查缺失、点名补挂并在后续查询确认，接口未知时不盲挂；**`sticker_send` 的描述就是常驻目录面**（v0.17.0）——能力句 + 激活区**分类全表**（`分类名 — 什么时候用这一类`，实机官方区 22 行 / 1095 字）+ 档位许可句，随库变更自动重挂（建类/删类/改说明/换区/导入后 ≤10 秒），且**描述里不写任何闸**（冷却/去重/概率照旧硬拦，只在她撞闸那一轮就地说明） |
| 面板 | hosted-tsx：**区 tab（新建/改名/说明/激活/拆区 3 秒确认）** + 分类分区墙（一格一图 + 就地聚焦卡）、新建/删分类、逐分类收图、总开关、**配表情积极度三档**。**零覆盖层弹窗**（平台坑，见 DESIGN 陷阱 20）；v0.10.2 起「她最近用过的」台账卡退场（后端台账保留，仍供去重/排序）；v0.14.1 起「她在跟谁说话」能解析出来（面板按钮不再报 `no_target`，见陷阱 27）；**v0.17.2 起墙上格子取 256px 缩略图**（服务端按内容指纹缓存，实机 190 张 34.7MiB → 2.33MiB；动图在格子里是首帧静态，点开聚焦卡才播动画） |
| 格式 | png / jpg / gif / webp（只认文件头），单张 ≤8MiB；gif 动图保动画直发 |
| 批量入库 | 分类头「收图进这一类」（多选，目标分类就是这一块，单轮≤64 张）；**「导入」选 `.zip` 直传**（v0.6.0 分块上传，manifest 随行带描述/标签/套图/梗义/**分类说明**）；高级旁路（v0.10.3 起面板无按钮无提示）：把图/包放进 `data/library/inbox/`，服务端 `import_inbox` 入口照旧整批收 |
| 防重复 | 入库记内容指纹（sha256），同图再传如实拒绝；旧图 lazy 回填 |
| 库体检 | `repair` 入口/面板按钮：清掉丢图的条目与孤儿文件，补旧条目指纹 |

## 开关语义

`[sticker_manager].enabled = false`（默认，fail-closed）：她不发图、看不到目录，
但库的收藏/编辑/删除照常可用。总开关在面板顶部或 `switch` 入口切换。

## 提醒间隔（v0.20.10）

面板「存在感注入」提供「提醒最小间隔（秒）」滑块，范围 **0–60 秒**，步长 1 秒。
拖动后点「保存」写入 `[sticker_manager.awareness].min_interval_sec`，当场生效并在重启后保留；
保存失败时保留原配置并显示错误。默认仍为 60 秒，旧配置中 0–60 秒的覆盖值保持不变，
超过 60 秒的值按新上限收敛到 60 秒。

**0 秒只关闭提醒的时间限制，不代表每轮必发图。** 轮数门槛仍跟随积极度（爱发 3 / 自然 6 /
矜持 12 轮）或自定义配置，情绪触发仍生效，冷却、去重、概率与工具即时发送规则不变。
「提醒轮数」展示提醒门槛与距上次成功提醒的累计轮数；时间限制内计数可能超过门槛。
设置修改不会清空计数，也不会立即补发提醒，仍由下一条新用户消息驱动。

## 频控与容量

- 同一角色卡两次发送之间默认冷却 20 秒（`[sticker_manager.send].cooldown_sec`）；
- **两级目录选图**：`sticker_list` 无词时先报【套图分类】再报条目，带 `group` 只看那一类；
  `sticker_send(group=)` 只拍板“这类调性对”，组内先过近期去重尺再随机选一张（id > group > query）；
  **零张的分类不出现在她的目录里、也不能被她选去发**（轮 I：分类是管理概念，不是发送目标）；
- **跨轮去重**：她自主选图时，同一角色卡最近 5 张成功发过的不再出现
  （`recent_dedup_count`，0=关；台账源，重启不失忆）；主人点名要再看某张时
  她可用 `sticker_send(force=true)` 绕行（冷却仍生效）；
- **配表情积极度**（三档 Select：矜持 / 自然 / 爱发；v0.19.0 起这一档**统一驱动三面**，
  v0.20.0 起工具描述那一面是**决策检查点 + 判据**两句）：
  ① 工具描述**第一句**要求她「开口之前先做一次判断：这句配上图会不会比纯文字更准」，
  后面才是触发判据（什么时候该想到配图）；② 静默提醒的**点名节奏**
  （矜持 12 轮 / 自然 6 轮 / 爱发 3 轮一次，v0.20.0 起这句只是**兜底**，见下条）；③ 提醒的措辞。
  默认「自然」；想让她更常配图选「爱发」，想安静选「矜持」——**这就是"积极发 / 不怎么积极"的开关**。
  想自己定节奏：在 `plugins/sticker_manager/config/plugin.toml` 里把
  `[sticker_manager.awareness].inject_interval_n` 写成具体数字（0 = 跟随档位）。
  **发送层的三把尺一口都不吃这一档**：`cooldown_sec`（节奏）、`recent_dedup_count`（最近不重复）、
  `probability`（放行闸）各自独立；切档当场生效（重挂工具描述 + 换节奏）。
  她每次成功发图后还会拿到一句下一步指引（`note`），那句话里不提任何闸。
- **存在感注入按话轮走，但只负责"想起来"**（v0.16.0 换驱动、v0.17.0 换载体）：她每开一轮
  （`bus.memory` 里的 `user_message` 前进）才是一个决策点。v0.17.0 起注入正文只剩三句
  （库有多大 + 去哪看目录 + 档位段）——**分类目录搬去了每轮都在场的工具描述**，因为
  `ai_behavior="read"` 是排干即弃的一次性 cue：文字模式等下一个话轮、语音模式要等下一次
  自然热切换（宿主 `lifecycle.py` 明写"哪怕隔好几个话轮"），装不了地图。
  节奏三键在 `[sticker_manager.awareness]`：`inject_mode`（`interval_n` 默认 / `every_user_message`）、
  `inject_interval_n`（**默认 0 = 跟随积极度档位**：矜持 12 / 自然 6 / 爱发 3 轮）、
  `min_interval_sec`（默认 60 秒，面板可调 0–60，0 关闭时间限制）。
  **v0.20.0 起多一根 `event_gated`（默认开）**：这句用户话里有情绪反应时（本地情绪词表 + 反应标点，
  v0.20.11 增加受限完整轻互动短句），
  不为这件事调用模型）**不等轮次攒满就点名一次**，上面那条轮次节奏退居兜底。触发源跟着"刚读完的
  这句话"而不是计数器，是同门 `forever_companion` 里她真会照着调的那类提醒的形状。
  想关掉点名的内容判据就写 `event_gated = false`，地板对它照样生效（不会变成每句都点）。
  面板显示提醒轮数与驱动，并提供最小提醒间隔滑块；轮数模式与门槛仍在配置文件里。
  总线读不通时自动退回
  `interval_sec` 的挂钟降级路径，`驱动` 那格会如实显示"降级时钟"；
- **本次运行读数（v0.17.1，只读不放旋钮）**：面板底部「本次运行」给四把数——她的话轮 / 她调用工具 /
  发出成功 / 被拦下，外加「常驻目录 N 类」（= 那份每轮都在场的描述里现在有几个分类）。
  **口径是开机到现在，重启插件归零**，不是"今日累计"。要判断"她到底爱不爱发"，
  先用够 30 轮以上再看这四把数——历史真实率约 2~3% 的话轮出一次发图，几轮的样本说明不了任何事。
  同一件事也进日志（`tool call: … outcome=refused reason=…` / `sticker_send surface applied: …`），
  所以"她没调工具"与"她调了但被闸拦下"从此分得开（以前两者在日志里长得一模一样）。
- **表情包独立成条**（v0.20.7）：正常回复走她自己的文字通道；`sticker_send` 保留可选
  `text`（≤500 字）兼容旧调用，但仅用于额外配文。非空时先发独立配文，再发独立图片，
  不在正文复述配文；留空只发图片。两条均署插件名，不冒充她的回复气泡。
  图片构造失败时不发配文；构造成功后两次传输仍可能部分成功，配文已提交但图片失败时
  如实标明，不自动重发配文。图片成功计数、冷却和去重仍只按那张图推进一次。
- **概率闸门**：`send.probability` 控制她发图意愿到实际放行的比例（默认 1.0=关）。
  同一角色卡一个复用窗口（`probability_reuse_sec`）内只掷一次判定，不叠加惩罚；
  **闸门与积极度是两把尺**：闸门拒她已下的决定，积极度改她想不想发——互不越界；
- ≤256KiB 的图走内联通道（保留原字节与 gif 动画），更大的静态图走宿主上传换 URL；
  动图超过内联预算会**如实拒绝**而不是被压平成 JPEG；
- 给模型看的目录默认最多 80 条（按最近使用排序），台账保留 200 条。
